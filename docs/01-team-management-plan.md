# Troop Website Team Management Plan

## Goal

Help 6 to 7 middle-school scouts build and maintain a useful troop website while learning basic project planning, web content, design, and quality control.

You will act as the project lead and coordinator. Your job is to organize the overall project, assign work, answer questions, review progress, and step in to fix or improve parts when needed. The scouts should still do the main project work, but you keep the work structured, small, and reviewable.

The scouts' current project goal is to create a working Troop 157 website with troop information, events/calendar, contact information, announcements, a mobile-friendly layout, and a safe organized design. The first version should prioritize those goals before adding extra pages or advanced features.

## Team Structure

Recommended structure:

- Project lead: you organize the project, keep the task board updated, run check-ins, help scouts when they are stuck, review work, and handle harder fixes or improvements.
- Scout contributors: the 6 to 7 scouts split the project workload evenly using small task packets.
- Peer reviewers: every scout reviews another scout's work before it comes to you.
- Adult reviewer: an adult leader reviews public-facing safety, contact information, event details, and photo use before launch.

Instead of giving each scout a permanent role for the entire project, divide the work into balanced assignments. Each scout should get a mix of content, layout, and review work so the project feels shared and everyone learns more than one skill.

The admin page should not be owned by one middle-school scout working alone. Treat it as a project lead/adult-supervised feature because it affects security, content publishing, and who is allowed to change public information.

## Your Role As Project Lead

Your responsibilities:

- Break large goals into small tasks.
- Assign tasks evenly across the 6 to 7 scouts.
- Keep a visible task board.
- Make sure every task has a reviewer.
- Help scouts who are blocked.
- Improve or fix code when a task is too technical for the group.
- Keep the website consistent.
- Coordinate adult review before launch.
- Make the final publish decision.

You should avoid doing all the work yourself. The goal is for scouts to build the site with your guidance.

## Scout Workload Model

Each scout should receive roughly the same amount of work. A good assignment packet includes:

- One content task.
- One page or section-building task.
- One review/testing task.
- One cleanup task near the end.

Example packet:

- Draft two announcements.
- Add those announcements to the announcements page.
- Review another scout's event section.
- Fix one mobile layout or spelling issue from the review checklist.

This keeps the work balanced and prevents one scout from getting all the easy writing tasks while another scout gets all the harder technical tasks.

## Adult And Youth Safety Boundaries

Use these rules before publishing anything:

- Do not publish youth last names, personal phone numbers, personal emails, school names, or home addresses.
- Do not publish photos unless the troop has permission to use them.
- Avoid captions that identify youth by full name.
- Use a troop-controlled contact email or contact form, not a scout's personal contact information.
- Review all public content with an adult leader before launch.
- Do not publish event location details if the troop considers them private or members-only.

## Meeting Rhythm

Use short, predictable meetings. Middle-school contributors usually do better with visible progress than long planning sessions.

Suggested weekly structure:

- 10 minutes: show what changed since last meeting.
- 10 minutes: review blockers and questions.
- 30 to 45 minutes: focused work time in pairs or small groups.
- 10 minutes: each scout states what they will finish before the next meeting.

Keep a visible task board with three columns:

- To Do
- In Progress
- Ready For Review
- Done

Move tasks only when the definition of done is met.

## Working Style

Use pairs when possible:

- One scout writes or edits.
- One scout checks instructions, spelling, links, and layout.
- Switch roles each meeting.

Keep assignments small:

- Good task: "Write two announcements and add them to the announcement list."
- Good task: "Create three event cards using the event template."
- Good task: "Check the contact page on phone width and list any problems."
- Too large: "Make the events page."
- Too large: "Build the admin page."

Use templates:

- Give every scout the same section pattern.
- Give every event or announcement task the same title, date, description, and status format.
- Give every reviewer the same checklist.

## Review Process

Nothing goes live without review.

Recommended review steps:

1. Scout completes the task and marks it Ready For Review.
2. Peer reviewer checks spelling, links, mobile layout, and privacy.
3. Project lead checks consistency with the site template.
4. Adult leader checks public-facing content and safety.
5. Project lead publishes or merges the work.

## Definition Of Done

A task is done only when:

- The assigned content is complete.
- The page or section works on desktop and phone width.
- All links go somewhere valid or are clearly marked as placeholders.
- Images have permission and alt text.
- Text does not include private youth information.
- Another scout has reviewed it.
- The project lead has accepted it.

## Suggested Timeline

Week 1: Orientation and website goals

- Explain the purpose of the website.
- Show the base template plan.
- Assign the first balanced task packets.
- Create the first task board.

Week 2: Content collection

- Gather troop facts, meeting info, event examples, announcement examples, approved photos, and contact requirements.
- Decide what should be public and what should stay private.

Week 3: First page drafts

- Draft home, events/calendar, contact, and announcements sections.
- Do not worry about polish yet.

Week 4: Template build

- Convert drafts into the base website template.
- Keep layout simple and consistent.

Week 5: Review and cleanup

- Test links, spelling, mobile layout, image permissions, and accessibility.
- Replace placeholders.

Week 6: Launch candidate

- Adult review.
- Final corrections.
- Publish the first version.

Week 7 or later: admin planning

- Decide who is allowed to update announcements, events, and troop information.
- Create an admin page mockup without real publishing power.
- Choose the safest technical approach before building a real admin feature.

After launch: maintenance

- Rotate maintenance tasks monthly.
- One scout updates upcoming events.
- One scout updates current announcements.
- One scout checks links and mobile layout.
- One scout checks photos and alt text.
- You review and publish the updates.
