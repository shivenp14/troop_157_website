# Troop Website Task Assignments And Sequence

## Project Phases

Build the site in this order:

1. Decide what the website must do.
2. Collect safe, accurate content.
3. Draft each page or section in plain text.
4. Build the base template.
5. Add each scout's section into the template.
6. Review for safety, accuracy, mobile layout, and spelling.
7. Publish the first version.
8. Maintain the site monthly.
9. Plan and build the admin page only after the public MVP works.

Do not start with advanced styling, animations, or extra features. The first version should be useful, readable, and easy to update.

## MVP Scope From The Scouts' SOW

The minimum viable product should include:

- Homepage with Troop 157 information.
- Events/calendar page with upcoming activities.
- Contact page with approved troop contact information.
- Announcement section for upcoming events and important updates.
- Mobile-friendly layout.
- Safe and organized layout.

Success means:

- The site works without major glitches or broken links.
- Every main category works.
- Visitors can use the site easily.
- Information is easy to find.
- The site helps scouts, adults, and leaders communicate more clearly.

## Balanced Assignment Model For 6 To 7 Scouts

You are the project lead. The scouts should split the project workload evenly using task packets instead of permanent roles.

Each scout should get:

- A content task.
- A build task.
- A review task.
- A cleanup or improvement task.

This makes the project fairer and helps every scout practice writing, building, testing, and improving the site.

## MVP Work Areas

The MVP work should be split across these areas:

- Homepage.
- Events page.
- Contact page.
- Announcements section or page.
- Mobile-friendly layout.
- Safety, privacy, and accessibility review.

## Example Assignment Packets

Use these as starting assignments. Adjust them based on scout skill level, attendance, and interest.

### Packet A: Homepage And Navigation

Content tasks:

- Draft a short homepage welcome message.
- List the 3 most important things a visitor should find first.

Build tasks:

- Add the homepage intro section.
- Add navigation links to the main pages.

Review tasks:

- Check that navigation labels are clear.
- Check that the homepage works on a phone-width screen.

Done when:

- The homepage explains who the troop is and points visitors to events, announcements, and contact information.

### Packet B: Events

Content tasks:

- Collect 3 to 5 public event examples.
- Write event titles, dates, short descriptions, and public location notes.

Build tasks:

- Add event cards or event rows.
- Make old or sample events easy to replace.

Review tasks:

- Check that private event details are not exposed.
- Check that event dates and descriptions are easy to scan.

Done when:

- Visitors can understand what is coming up without seeing private troop information.

### Packet C: Announcements

Content tasks:

- Draft 3 to 5 short announcements.
- Decide which announcements are current and which are examples.

Build tasks:

- Add the announcement list.
- Add a latest-announcement preview on the homepage if needed.

Review tasks:

- Check that announcements are short and clear.
- Check that old announcements can be removed or archived.

Done when:

- The site can show important updates clearly.

### Packet D: Contact

Content tasks:

- Draft the contact page using only approved public contact information.
- Write instructions for families who want to ask questions or visit.

Build tasks:

- Add the contact page sections.
- Add contact links or contact text in the footer.

Review tasks:

- Check for unsafe personal information.
- Check that the contact path is easy to find from every page.

Done when:

- A visitor knows how to contact the troop safely.

### Packet E: Visuals And Media

Content tasks:

- Collect approved photo options.
- Write captions without youth full names.

Build tasks:

- Add approved images where they help the page.
- Add alt text for every image.

Review tasks:

- Check image permissions.
- Check that images do not make text hard to read.

Done when:

- Images improve the site and follow privacy rules.

### Packet F: Mobile And Accessibility

Content tasks:

- Create a list of common things to test.
- Write down issues clearly as fix-it tasks.

Build tasks:

- Help fix spacing, text size, link labels, or layout problems.
- Make simple improvements after review.

Review tasks:

- Test every main page on desktop and phone width.
- Check links, headings, alt text, and spelling.

Done when:

- The MVP is easy to use on both desktop and phone.

### Adult-Supervised Work: Admin Page Planning

The admin page should be planned by you with adult support later. It should not be part of the current starter template and should not be assigned as an unsupervised scout task.

First tasks:

- Decide who should be allowed to log in.
- Decide what admins can edit: announcements, events, contact information, and homepage text.
- Create a paper or static mockup of the admin page.

Later tasks:

- Choose the technical approach for authentication and data storage.
- Build the real admin page only after the public MVP works.

Done when:

- Admin permissions are clear.
- The admin page cannot be used by random visitors.
- Every admin change can be reviewed or corrected.

## Task Order By Week

### Week 1: Setup And Scope

You:

- Explain the website purpose.
- Explain that you will coordinate the project and the scouts will split the work evenly.
- Assign the first task packets.
- Create the task board.

All scouts:

- Review safety and privacy rules.
- Look at 2 or 3 example troop or youth organization websites.
- Write down what the troop website must include.

### Week 2: Content First

Packet A scout:

- Draft welcome text and visitor priorities.

Packet D scout:

- Draft safe contact page content and visitor instructions.

Packet C scout:

- Draft sample announcements and announcement fields.

Packet B scout:

- Draft event fields and sample events.

Packet E scout:

- Collect approved media and draft alt text.

Packet F scout:

- Build the first review checklist.

### Week 3: First Full Draft

All packet owners:

- Convert notes into finished first drafts.
- Peer review another scout's draft.

You:

- Resolve duplicates and inconsistent wording.
- Confirm what can be public.
- Rebalance tasks if one scout has too much or too little work.

### Week 4: Template Assembly

You:

- Create the base template files.

Scouts:

- Add their assigned content into the matching section.
- Keep the layout simple.

Packet F scout:

- Check desktop and phone layout.

### Week 5: Polish And Safety Review

All scouts:

- Fix review comments.
- Replace placeholders.
- Check links.

Adult leader:

- Review public content, photos, and contact information.

### Week 6: Launch

You:

- Publish the first version.
- Record how to update the site.

All scouts:

- Do one final walkthrough.
- Pick the next monthly maintenance assignments.

## Backlog Ideas After Launch

Add these only after the first version is live:

- Real admin page with login.
- News posts or trip reports.
- Downloadable forms.
- Member-only area.
- Embedded calendar.
- Photo albums by event.
- Donation or fundraising page.
- Search.
- Newsletter signup.

## Rules For Assigning Work

- Assign balanced task packets instead of permanent page owners.
- Give every task a reviewer.
- Keep each task small enough to finish in one meeting or one week.
- Do content before styling.
- Do safety review before publishing.
- Rebalance work if one scout finishes early or gets stuck.
- Rotate maintenance work after launch so the same scout is not always doing the same task.
